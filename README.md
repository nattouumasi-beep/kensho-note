# 懸賞ノート（半自動・安全重視）

広告なし・外部ライブラリなしの静的Webアプリです。無料懸賞の**候補**を一覧にして「保存」「応募済み」「非表示」で管理します。フォームの自動送信、Xへの自動フォロー・いいね・リポスト、CAPTCHA突破は行いません。

## まず試す

1. **最も簡単なのは** `お試し用_懸賞ノート.html` をPCのブラウザで開く方法です。通常版の `index.html` でも動作します。iPhoneのローカルHTMLの読み込みには制約があるため、iPhoneで使うにはサイト公開をおすすめします。
2. 最初は架空の3件の**サンプル**が表示されます。サンプルは実際のキャンペーンではありません。
3. 「自分で追加」で実際の応募案内ページを登録できます。リンクを開いて条件を確認後、「応募済みにする」を押すだけです。
4. 応募履歴と保存済みの候補情報はブラウザのローカル保存です。フィードから掲載が消えても、応募済み・保存済みの履歴は残ります。機種変更・キャッシュ消去に備え「バックアップ・設定 → JSONで保存」を使ってください。

## 自動収集について

`python scripts/update_feed.py` を実行すると、**PR TIMES の公開RSS**（`https://prtimes.jp/index.rdf`）から「抽選」「当たる」「プレゼントキャンペーン」などを含む**候補タイトル**を抽出し、`data/campaigns.json` に追加します。RSSにはキャンペーンに関係のないニュースや応募期限切れも混ざり得ます。応募資格の確認は行っていません。応募フォームのURLではなく、PR TIMESの案内記事を開きます。

GitHubに新しい専用リポジトリを作ってこのフォルダを配置し、Actionsを許可すると、毎朝8:13頃（日本時間・GitHubによる遅延あり）に候補一覧を更新する設定が入っています。**専用リポジトリへの登録を進めています。**

GitHub Pages を使う場合は、公開リポジトリの Settings → Pages で `Source: GitHub Actions` を選びます。日次収集ワークフローがデータ更新後に直接Pagesも公開するため、GitHub Actionsによる自動コミットでサイト再公開が起動しない問題を避けます。公開URLを得るためにリポジトリとソースコードが公開されます。公開が不都合なら、別の非公開ホストを検討してください。既存の「私の比較ノート」には手を加えません。

## 情報の扱いと安全性

- このアプリは氏名・住所・電話番号・SNSパスワードを入力させず、外部にも送信しません。
- 入力した応募履歴と応募済み・保存済みの候補の一部情報はそのブラウザのストレージ内だけに保存します。別端末とは同期しません。
- 自動収集はRSSから公開済みのタイトルとリンクを読むだけで、応募先にはアクセスしません。
- RSSの記事は主催者の応募フォームとは限りません。リンク先から主催者の公式案内に進み、期間・応募資格・利用規約を毎回確認してください。
- SNSでの操作は完全に手動です。繰り返し応募、複数アカウント応募、アクセス制限回避はしないでください。
- 公開する際も、`data/campaigns.json` に個人情報を入れないでください。
- PR TIMESのフィード仕様変更、通信失敗、GitHub Actionsの停止などにより収集が途切れることがあります。
- 取得対象は最長90日前までの直近RSS掲載記事です。高精度な「無料懸賞」判定を保証しません。

## ファイルの役割

- `お試し用_懸賞ノート.html`: 1ファイルで試せる単体版（自動収集への接続なし）
- `index.html`: 本体の画面
- `assets/styles.css`: スマホ対応デザイン
- `assets/app.js`: 検索・保存・履歴・バックアップ
- `scripts/update_feed.py`: RSS候補収集スクリプト（Python標準ライブラリのみ）
- `.github/workflows/update-campaigns.yml`: 日次の候補更新
- `data/campaigns.json`: 公開情報のみ保存
- `tests/test_feed.py`: 収集処理の基本テスト

```bash
python -m unittest discover -s tests -v

# http://localhost:8000 を開く
```

**注意：** この段階ではサイト公開も自動収集の定期実行も開始していません。定期実行には専用のGitHubリポジトリへの配置、Pagesを「GitHub Actions」方式で有効化する操作が必要です。

## サイト公開の最短手順（GitHub Free）

1. GitHubで **新規の公開リポジトリ** `kensho-note` を作成し、最初に `README.md` を追加してください（`main` ブランチができます）。**既存の私の比較ノート用リポジトリは変更しません。**
2. このサイト一式をそのリポジトリのルートに配置します。チャットのGitHub連携を利用すると、作成後のアップロード作業をアシスタントに依頼できます。
3. リポジトリの **Settings → Pages → Build and deployment → Source** を **GitHub Actions** に変更してください。
4. **Actions → Update candidates and publish site → Run workflow** を一度実行します。以後は毎日08:13（JST）頃に更新・再公開する予定です。GitHubのスケジュールは時刻どおりとは限りません。
5. **Settings → Pages → Visit site** からアクセスし、iPhoneのSafariで「ホーム画面に追加」すると開きやすくなります。

**注意**：公開リポジトリのファイルと公開Pagesサイトは他の人も閲覧できます。氏名・住所・SNS認証情報・応募履歴をリポジトリへ追加しないでください。応募履歴はローカル保存で、サイト公開によって共有されるわけではありません。

**初回収集の実データ検証は未完了**：開発環境からRSSサーバーに直接接続できないため、日次処理が初回実行されるまでは懸賞件数がゼロになる場合があります。収集ゼロや失敗は応募案件がない証拠ではありません。
